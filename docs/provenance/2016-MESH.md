## Native storage contract

- **ReadFileMesh**, entry **0x012a8a01**, finds the first LF, throwing if absent.
  It compares only the first twelve bytes with the supported version strings,
  then starts the body after that LF. CRLF and a suffix before LF are accepted.
- Strings: **0x0192fed5** (1.00), **0x0192fee2** (1.01), **0x0192feef** (2.00).
  Text branches pass scales 0.5 and 1.0 respectively; text decoding is not implemented.
- The v2 header is 12 bytes: little-endian u16 header size, u8 vertex stride,
  u8 face stride, u32 vertex count, u32 face count. Instructions at
  **0x012a8b2b** and **0x012a8b38** require size 12 and stride word 0x0c24:
  36-byte vertices and 12-byte faces. Both counts must be nonzero.
- It copies count × 36 vertex bytes, then count × 12 face bytes, requires the
  final cursor to equal input length (**0x012a8cc2**), and checks every unsigned
  face index against vertex count (**0x012a8ce6** onward).
- The helper at **0x012a9295** bounds cursor plus byte count against string length,
  copies bytes and advances the cursor, otherwise throwing. Native arithmetic is
  32-bit. Our checked host-size arithmetic and size limit deliberately restrict
  pathological inputs; native overflow/unsafe allocation behavior is not replicated.
- **WriteFileMesh**, entry **0x012a91bf**, writes version line, header and raw
  storage. Vertices contain three position, three normal and three UV float words;
  faces contain three zero-based u32 indices.
- This reader branch does not reject non-finite floats. The Rust decoder preserves
  NaN payloads and signed zero; the diagnostic rejects non-finite inputs separately.
  The native reader calls bounding-box computation after decoding. Our diagnostic
  bounds are not claimed as an emulation of that function.

All **37** bundled meshes are v2.00: **10,992 vertices**, **12,896 triangles**.
SHA-256 comparisons show all 37 matching 2015 mesh payloads are identical. Its
Rust reader nevertheless differs: strict LF prefix and finite-float rejection
are narrower than observed native 2016 acceptance. No reader, simulation or
rendering code was transplanted from the 2015 project.

## Character input

character3.rbxm is XML v4 with 26 instances: one Model, seven Parts, one Humanoid,
one SpecialMesh, two Decals and **14 Attachments**. The 2015 template has the same
counts except it has no Attachments. Part size/shape use lowercase serialized keys;
CFrames store X/Y/Z and R00..R22 rows. Only explicit Part fields/hierarchy are
imported; Attachment transforms, mesh/decal dispatch and Humanoid behavior are
unimplemented. Matrix interpretation is fixture-tested, not native-execution compared.

## Verification and limits

`sh tools/cargo.sh test --locked` passes eight synthetic tests. Mesh cases cover
every truncation of an invented triangle, invalid layouts/counts/indices, trailing
bytes, CRLF/suffix handling and exact float words. The original-bundle diagnostic
passes 120 headless Bevy updates. Native instruction emulation, whole-loader
differential execution, graphics and full native parity are **not tested**.
